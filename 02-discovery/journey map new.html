  1. Discover

    User Action
    • Types attendance vs capacity in plain words → gets relevant assets, not exact-name matches.
    Internal State
    • Hurried but hopeful → expects an answer in seconds, not twenty minutes.
    Pain Point Addressed
    • Exact-name-only search (BUG-2042) → intent-based search handles inconsistent venue naming.

  2. Understand

    User Action
    • Sees one recommended answer with its definition → knows what "attendance" means before using it.
    • Compares lookalike dashboards side by side → sees why their numbers differ.
    Internal State
    • Oriented → stops guessing between lookalike dashboards.
    Pain Point Addressed
    • Three attendance definitions (BUG-2058) → definition shown beside every result.

  3. Trust

    User Action
    • Checks official badge, owner, refresh time → confirms the number in seconds.
    Internal State
    • Assured → can explain the number before presenting it.
    Pain Point Addressed
    • No trust indicator (BUG-2061, BUG-2080) → certification, owner, freshness visible on every asset.
    • Three conflicting per-capita figures (Marcus) → one marked official, others flagged.

  4. Decide

    User Action
    • Takes number into briefing → no spreadsheet or Data team message needed.
    • Saves or shares the view → colleagues reuse the same source.
    Internal State
    • Decisive → the platform is where the decision started.
    Pain Point Addressed
    • Local views, drifting Excel exports (BUG-2077, UXR-11) → saved views stay linked to source.
    • Duplicate requests (BUG-2091) → existing asset suggested before a new request.

3 Competitive Advantages Over the Manual Workaround

  1. Speed: One search replaces a twenty-minute scroll → answer arrives before the briefing.
  2. Verifiability: Badge, owner, refresh time shown → number is defensible; spreadsheets can't show these.
  3. Compounding reuse: Answers stay on-platform → next user benefits; workarounds stay private and drift.

Caveats: Based on illustrative sample data; capabilities are design hypotheses. Understand comes before Trust because a badge can't settle a conflict until users know what each number means. Trust depends on reconciling KPI definitions first (BUG-2058); a badge on conflicting numbers only labels the conflict. "Intelligent" here means intent-based search only; the research doesn't mention AI features. "Seconds" is an aspiration with no measured baseline. Marcus's current-state steps are inferred.
