# Competitive Analysis & Journey Map (Module 2)

## Responses
- **Role, who are you solving for? (the specific user segment or profile):** An Asset Manager / Business Leader responsible for monitoring asset performance and using data to support leadership and operational decisions.
- **Goal, what is this user ultimately trying to achieve?:** Quickly understand how the asset is performing, what has changed, and what requires attention using information that can be trusted without additional validation.
- **Friction, the main barrier (moment of misery) stopping them from succeeding:** The user finds a KPI but is uncertain whether it is current, approved, or consistent with the underlying business data, so they contact the Data team to validate the number before using it in a leadership discussion.
- **External tools, the outside platforms or tools the user is forced to use:** Source-system / operational reports: used to cross-check whether the KPI shown in Assets InsightHub matches the underlying business data.
Excel / spreadsheets: used where information is manually maintained or where users need to compare/reconcile numbers outside the platform.
Separate KPI glossary or documentation: used to check KPI definitions, calculations, ownership, source, or refresh frequency.
Communication tools such as Teams or email: used to contact the Data team and ask them to confirm whether a number is correct, current, and approved.
- **The process, the 3 to 5 manual steps the user takes to get the job done:** Find the KPI in Assets InsightHub.
Cross-check the number against the underlying source report or spreadsheet.
Check the KPI definition and freshness to understand how it was calculated and when it was last updated.
Contact the Data team through Teams/email when there is a discrepancy or uncertainty.
Wait for confirmation, then use the KPI in the leadership discussion.
- **Core frustration, the exact moment the process feels most “broken”:** “I have the KPI in front of me, but I still can’t trust it enough to use it in a leadership meeting without asking someone to validate it first.”
- **The evidence, a specific quote or behavior from the research that proves this:** “I have the dashboards, but when leadership asks me a question I still sometimes need to go back to the Data team to confirm which number or KPI definition I should use.”
- **Your journey map, a shareable link, or the map file you committed (e.g. journey-map.html):** Below is a one-page future-state journey that directly removes the manual validation loop. I’d structure it around a simple progression: Discover → Trust → Understand → Decide.

Assets InsightHub: Future-State Journey

Persona: Asset Manager / Business Leader
 North Star: From finding a KPI to confidently acting on trusted insight.

Visual timeline

1. DISCOVER → 2. TRUST → 3. UNDERSTAND → 4. DECIDE
 Find the right insight → Verify instantly → Understand what changed → Act with confidence

1. Discover the Right Insight
User Action: Ask/select business question → Relevant asset KPIs and insights surface immediately.
Internal State: Unified discovery experience → Relevant information becomes easier to find.
Pain Point Addressed: Searching multiple dashboards → Reduces navigation and fragmented discovery.

User mindset: “I know where to find the answer.”

2. Trust the Data
User Action: View KPI trust context → Confirm freshness, definition, source, and certification immediately.
Internal State: Certified governed data → Consistent KPIs provide decision-ready information.
Pain Point Addressed: Manual cross-checking → Removes repeated validation with reports and Data teams.

User mindset: “I know this is the right number.”

3. Understand What Changed
User Action: Explore performance changes → See exceptions, trends, and relevant drivers together.
Internal State: Analytics and AI interpret trusted data → Turn metrics into decision-oriented insights.
Pain Point Addressed: Manually interpreting charts → Shortens the path from data to understanding.

User mindset: “I understand what changed and why it matters.”

4. Decide & Act
User Action: Use trusted insight in leadership discussion → Make decisions without separate validation.
Internal State: Insight remains traceable to governed data → Maintain confidence during decision-making.
Pain Point Addressed: Waiting for Data-team confirmation → Removes the final dependency before action.

User mindset: “I can confidently use this insight to make a decision.”

Competitive Advantages vs. Manual Workaround

Immediate trust → Faster decisions
 Removes cross-checking across source reports, spreadsheets, documentation, and Data-team validation.

Unified context → Less fragmentation
 Brings discovery, KPI context, trusted data, and insights into one experience.

Self-service confidence → Greater scalability
 Enables leaders to answer recurring questions without making the Data team the manual trust layer.

The transformation

Today:
 Find → Question → Cross-check → Ask → Validate → Interpret → Decide

Future:

Discover → Trust → Understand → Decide

That final line is especially strong for your Product School project because it connects the persona, problem hook, workaround, value proposition, and future-state experience into one simple product narrative.
